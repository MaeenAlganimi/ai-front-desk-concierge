# Qudra Concierge - build spec
Agentic AI front desk for appointment-based small businesses (demo business: "Noor Dental & Beauty Studio", fictional). Bilingual EN/AR with RTL. Next.js 15 App Router, TypeScript, Tailwind v4, lucide-react icons only. No fake stats/testimonials/reviews. Fictional address only, no real city/country names.

## Data layer
PGlite (@electric-sql/pglite with `vector` extension from '@electric-sql/pglite/vector') persisted to ./.data/pglite (memory:// in tests/evals), schema in src/lib/db/schema.sql, seed in src/lib/db/seed.ts (services, staff, opening hours, 2 weeks of appointments relative to today, customers, FAQ/knowledge base chunks EN+AR). Tables prefixed concierge_: customers, services, staff, appointments, reminders, conversations (with pending_action jsonb, customer_id, lang), messages, tool_calls (trace: conversation_id, turn, step, tool, args jsonb, result jsonb, latency_ms, kind: tool|guardrail|confirm, created_at), handoffs, kb_chunks (content, lang, embedding vector(768)). Singleton db in src/lib/db/index.ts (globalThis cache). Mark next.config serverExternalPackages: ['@electric-sql/pglite'].

## Agent (src/lib/agent/)
- llm.ts: interface LLM; GeminiLLM uses @google/genai, model gemini-2.5-flash, functionDeclarations; embeddings gemini-embedding-001 with outputDimensionality 768. MockLLM: deterministic rule-based planner (regex EN+AR incl. dialect words like "ابي/ابغى/بدي/عايز موعد", "الغي", "أجّل/غيّر موعدي") that emits the same tool calls so the app runs and evals pass with no key. Use Gemini if process.env.GEMINI_API_KEY else mock. Mock embeddings: hashed bag-of-words 768-dim, normalized.
- tools.ts: zod-validated tools: check_availability(service, date_from, date_to, after_time?, staff?), lookup_customer(phone|name), book_appointment, reschedule_appointment, cancel_appointment, create_reminder, answer_from_knowledge_base(query) (pgvector cosine top-k), create_handoff(reason, summary, priority). Real conflict detection against opening hours + existing appointments.
- loop.ts: runAgent({conversationId, message, customerPhone, confirm}): load memory (last N messages + customer profile summary), system prompt, iterate up to 6 function-call steps, record each tool_call row with latency. WRITE tools (book/reschedule/cancel/reminder) are never executed immediately: the agent's proposal is stored as pending_action on the conversation and a confirmation question is returned; it executes only when the user confirms ("yes"/"نعم"/"اكيد"/"تمام") or the UI confirm button sends confirm:true. Multi-write plans (reschedule + reminder) are bundled into one pending action. Guardrails in guardrails.ts: prompt-injection detection ("ignore previous instructions", "system prompt", "you are now", "developer mode", role spoofing, Arabic equivalents) -> refuse + log a guardrail trace row; medical-advice detection (dosage, diagnosis, "what medicine") -> no advice, offer booking/handoff; tool outputs wrapped as data. Reply in the user's language.
## API
POST /api/chat {conversationId?, customerPhone?, message, confirm?:boolean} -> {reply, trace[], pendingAction?, conversationId, mode:'gemini'|'mock'}. GET /api/dashboard/appointments, /api/dashboard/conversations, /api/dashboard/conversations/[id] (messages + trace), /api/dashboard/handoffs (PATCH to resolve), /api/dashboard/analytics. CORS for widget (OPTIONS too).
## UI
- / : polished demo business landing page (hero, services with prices, team, hours, FAQ), EN/AR toggle setting dir=rtl, embeds widget via <script src="/widget.js" data-business="noor"> (use next/script).
- public/widget.js: vanilla JS, one script tag, floating launcher, shadow DOM chat panel, quick-reply chips, renders confirm/cancel buttons on pendingAction, auto RTL for Arabic text, stores conversationId+phone in localStorage, asks phone once.
- /dashboard: staff console: week calendar (polling 3s), conversations list + transcript, Agent Trace panel (vertical timeline per turn: step number, tool name, args JSON, result JSON, latency, guardrail/confirm events with colored badges) - make this beautiful, it's the wow; handoff inbox with resolve; analytics from real DB data (agent bookings, handoff rate, avg tool steps per turn, languages, guardrail blocks). Clean modern design (zinc/teal), Inter + IBM Plex Sans Arabic via next/font/google.
## Tests
- vitest unit tests in tests/: availability/conflicts, guardrails, mock planner parsing.
- evals/run.ts (npm run evals, via tsx): scenarios in evals/scenarios.ts: simple booking EN with confirm, conflict -> alternative offered, multi-step "move my Thursday cleaning to next week after 5pm and remind me", cancel, KB question (price/parking), Arabic Gulf dialect booking, Egyptian dialect question, prompt-injection attempt (must refuse, no write), medical advice request (no diagnosis; offers booking), handoff request, write without confirmation must NOT change DB. Each asserts on tool calls + db state + reply. Prints pass/fail table, writes evals/results.md. Fresh in-memory PGlite per scenario. `npm run evals:live` uses the Gemini key (same scenarios).
